# 评审报告：《通用视觉游戏 Agent Runtime 技术规格说明书》

- 日期：2026-07-29
- 类型：专项评估（外部文档评审 + 本项目适配决策）
- 原文：`docs/reference/通用视觉游戏 Agent Runtime 技术规格说明书.docx`（另一 AI 撰写，Draft 0.1.0）

## 背景

用户引入该说明书作为项目演进参考，要求评审其优缺点与可行性，并据此修改本项目。说明书定义了一个多模型、多速率的游戏 Agent Runtime（感知/语义/技能/规划/记忆/仲裁全套）。

## 评审结论

### 优点（方向正确，应吸收）

1. **多时间尺度控制 + 高层模型不进高频回路**（§2.3/2.4）：与本项目"LLM 不进实时决策"红线一致且更精细
2. **技能生命周期 + 可抢占**（§2.5/5.9）：直接命中本项目当前痛点——每 tick 重新决策导致动作离散僵硬；技能在生命周期内连续闭环控制是正解
3. **动作仲裁 + 动作有效期**（§9）：多控制源（反射/导航/人工）抢同一套键鼠时的必需机制，本项目当前缺失
4. **证据绑定 / 置信度 / 有效期 / 防上下文污染**（§5.5/12/17）：M2 复盘质量的关键约束
5. **安全层**（§14/18）：全局急停、失焦立即释放输入、人工接管——真机发真实输入的必备品
6. **Phase 1 方法论**（§22）：先跑最薄闭环验证基础模型能力上限，不先写大量规则——方法论正确
7. 边界声明（§3.2 不做反作弊规避/注入/内存修改）与本项目保守路线一致

### 缺点

1. **范围失控**：Boss 攻击事件分割（§7.5）、在线策略更新、Phase 7 行为蒸馏属研究级目标，2070s 单机 + 无数据集不现实
2. **零实测数据**：全文频率/预算均"由测试确定"，无已验证的延迟与显存数字——是愿景文档，不是可执行规格
3. **多模型矩阵无落地路径**：fast vision/tracker/scene classifier/tactical/policy 等未指定任何具体模型，隐含巨大训练与数据工程，文档未估算
4. **VLM 参与 1-10Hz 探索决策与 8GB 显存跑游戏冲突**，无解法
5. 接口描述为 TypeScript 风格，与本项目 Python 栈不符（次要）
6. 评估体系（§16）为一整套 QA 工程，当前阶段投产比低

### 可行性判定

| 内容 | 判定 | 说明 |
| --- | --- | --- |
| 技能生命周期 + 抢占 | 现在吸收 | 治"动作僵硬"的正解 |
| 动作仲裁 + 有效期 | 现在吸收 | 为反射/人工接管铺路 |
| 安全层（急停/失焦释放/接管） | 现在吸收 | 真机必备，成本低 |
| 观测带置信度/证据/有效期 | 轻量吸收 | GameState 渐进升级，不另起 Observation Store |
| Trace 延迟统计 | 现在吸收 | 成本低，验收必需 |
| VLM 低频导航 | 留作可选实验 | 2070s 显存冲突未解 |
| 多模型感知矩阵、行为蒸馏 | 不做 | 超出当前资源 |
| 全套评估体系 | 不做 | 只保留延迟与基本计数 |

## 适配决策（范围边界）

做：技能化重构（ExplorationSkill/CombatSkill + 生命周期五态）、Action Arbiter（优先级+有效期）、安全层（F12 急停、失焦释放）、GameState 加 frame_id/置信度透传、主循环延迟 trace。

不做：Observation Store、Event Bus、Goal Manager/Planner、拓扑记忆、VLM 导航、行为蒸馏、全套评估指标。

依据：AGENTS.md 禁止提前搭建用不到的架构层级；说明书 §24.2 自评"截图→识别→固定流程"类项目应抽出基础抽象再迁移——本项目按此执行，六个抽象中先落 Skill/Action/Event（事件以信号量形式内嵌，不建总线）。
